# Política de versões válidas

## Regra principal

Nunca alterar diretamente a última versão válida.

## Cada alteração deve ter

1. versão estável de origem
2. branch própria
3. checkpoint
4. escopo/bloco definido
5. alteração
6. testes automáticos
7. preview
8. aprovação
9. commit
10. publicação
11. validação pública
12. nova marcação de versão válida

## Conteúdo cotidiano

Alterações comerciais serão feitas na Central online como rascunho.

## Layout

Alterações serão feitas em blocos.

## Regras de negócio

Alterações funcionais serão tratadas separadamente das alterações visuais.

## Rollback

A versão anterior nunca é excluída quando uma nova versão é publicada.
